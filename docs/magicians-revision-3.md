# Revision 3 (reply to be posted in the discussion thread, under the reply to the first review)

Revision 3 is on the pull request (https://github.com/ethereum/ERCs/pull/2113) and in the repository (https://github.com/garyyang-finchip/agent-safety-framework); the first post is updated. It carries the two fixes announced above, as implemented and tested, and nothing else of substance.

## What changed

**1. The response set in force is returned per clause and defined over the whole chain.** `check` now returns `(verdict, reasons[], restrictions[])`. The set for a clause is the union of the response sets of every suspended record among the clause binding and its ancestors, and it is empty when any record in that chain is terminated or outside its validity window (a chain that is not in force keeps no path open). `checkBinding` returns the same set with `Suspended` and with `ParentNotSatisfied`. Consumer rule 11.3 now says that a consumer applies the set the check returns, for both reasons, and never reads it from the clause binding's own record, which carries no set while an ancestor is suspended. `ASFGuardedAccount` follows that rule. Tests: N50 (union over a three-level chain; a full stop anywhere is in the union; a terminated or expired record empties it), N52 (a de-risk-only suspension of the root blocks new exposure through the derived binding and keeps repay and cancel open; the guardian's resume reopens), N53 (full stop or termination on the root closes the de-risking path), N54 (child and parent sets combine; full stop on either side dominates).

**2. Clauses can require interveners.** `Clause` gained `Intervener[] interveners`: each entry is an account and a rights bit set the binding must grant to that account; a zero account stands for some intervener other than the adopter. The adopter is never an intervener, so a requirement cannot be met by self-control. Mismatch is the new reason `IntervenerMismatch`, evaluated after the enforcement check and before the ancestor walk; malformed rights (0 or above 7) make `check` and `requirementId` revert. The tender example requires the task publisher with the suspend right, and the worker's self-adopted binding names it. Tests: N51 (named account, rights subset, adopter never counts, wildcard, several required interveners, malformed rights), N55 (a fulfiller whose binding is under its sole control is rejected with `IntervenerMismatch`; one naming the publisher is accepted and paid through the kernel).

**3. An intervener's suspension is not the adopter's to lift.** The registry records `suspendedBy`. When it is not the adopter, `resume` reverts for the adopter and succeeds only for an intervener holding `RIGHT_RESUME`; the adopter's own suspensions remain liftable by the adopter or by an intervener with the right, and the adopter keeps `RIGHT_TERMINATE` in every state. Tests: N16 (updated: the adopter cannot lift a suspend-only guardian's stop and can only terminate), N49 (guardian suspends, adopter cannot resume, an executor with the right can; the adopter's own suspension is lifted by either; the executor's suspension cannot be lifted by the adopter or by a suspend-only guardian), N35 (updated wallet path: the principal cannot lift the guardian's suspension, the guardian does), N56 (the publisher suspends the fulfiller's binding; the fulfiller's resume reverts; judgment rejects; a fresh binding that names the publisher again is admitted and the publisher can suspend it again).

**4. Examples and evidence script.** The personal-assistant example gives the guardian suspend and resume rights, since a suspension it records can no longer be lifted by the principal; the governance/intervention profile descriptor states the rule; the evidence script reads interveners from the relinked manifest, the guardian resumes in the guard loop, and the adapter template carries the publisher as a required intervener. Re-rehearsed on Anvil: 36 transactions across five phases, all successful.

**5. Identifiers.** The `IASFBindingRegistry` interface identifier is `0x1ff33bef`. `requirementId` values changed with the clause encoding, whose ABI type is now `tuple(uint8,uint16,tuple(address,bytes32,uint32[],address,bytes32,bytes32,uint16,tuple(address,uint8)[])[])`; the vector carries a clause with a named and a wildcard required intervener. The derivations of `specId` and `bindingId` in Section 3 are unchanged. Section 13.4 now states that while the proposal is a draft the clause struct and therefore `requirementId` values and interface identifiers may change between revisions.

## Stated residual

The adopter of a suspended binding can still terminate it and adopt afresh. The registry keeps this attributable (terminated record with its `suspendedBy`, new identifier and `createdAt`) and a requirement that names an intervener is met only by a binding that names it again, so the intervener's power returns with the binding; a consumer that must refuse replacements pins the binding identifier it admitted. A "created before" clause member is listed as an open point and as question 5 in the first post.

Suite: 82 tests, 56 negative conformance scenarios (N01–N56). Lint and the clean-copy verification are unchanged.
